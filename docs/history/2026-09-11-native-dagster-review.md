## 3. Invariants and boundary assessment

- **One document state:** native events and IO carry existing bounded reference messages. They do not create another DocSpec run ledger, result authority, plugin registry or dependency container. Reconciliation still admits the complete exact task population and retained evidence.
- **Stable recovery:** native run IDs and local concurrency do not change document work identity. Roots, accepted producers, fetcher/stage/processor settings, evidence time, sink, partition choices, deadline and index cap remain verified through the existing composition and prepared-worker checks.
- **Honest limits:** the renamed index cap bounds each prepared worker's disposable membership database. It does not claim to bound aggregate scratch, memory, provider concurrency, request rate or physical network traffic. Existing document work limits and fetcher-specific limits remain in their current owners.
- **Lifecycle ownership:** native generator resources close prepared workers after execution unwinds. The adapter closes task streams on early exit. The earlier general `FetchStream.__exit__` correction preserves an active interruption or integrity error if cleanup also fails; it adds no cancellation state or API.
- **Source outcomes are distinct:** the probe's permitted missing-document case returns an ordinary completed task with retained document failure evidence, while native retry events remain absent. Native worker failure and document refusal have different meanings.
- **Optional dependency:** adapter loading remains lazy; core exports no longer expose removed wrappers. The new example explicitly requires Dagster; core import/package checks preserve ordinary use without it.

The cancellation fixture correctly distinguishes a requested stop from an unexpected interrupt. Installed Dagster `execution/api.py:757` catches interruption and `:766` uses the recorded `CANCELING` state to decide its terminal event. `launcher/default_run_launcher.py:161` records that requested transition before sending its own cancellation request. The probe sets the request, not the terminal result; child interruption, cleanup and final native status remain observed assertions. It qualifies the native multiprocess executor path, not the launcher's gRPC cancellation transport, daemon, UI or hosted deployment.

## 5. Findings and resolutions

1. **Saved scheduler claims and duplicate composition — resolved.** The old handoff always described a local-threaded scheduler and carried unenforced fields. The worker-only profile, native resource map and removal of unused wrappers address the actual ownership problem without a new adapter schema.
2. **Vocabulary was repinned from mutable current bytes — resolved.** The example now reads the retained plan's independent resource pin and exact processor description before accepting bytes. The installed probe changes only those bytes and expects refusal.
3. **Native stop proof initially lacked a cancellation request — resolved.** An unrequested signal correctly produced an unexpected-termination failure. The final probe follows the native requested transition before parent signaling, while retaining real child/cleanup/status checks. The guide explicitly excludes launcher transport and deployment qualification.
4. **Resumed acceptance initially lacked final value/accounting assertions — resolved.** Probe lines `:229` and `:240` now verify captured counts/exact bytes and local-reference phrase values after recovery, alongside observed fetch/extractor calls.
5. **Stale active references — resolved.** Conformance matrix selectors now point to retained native/subprocess checks. The normative text names the actual handoff identity/profile reference metadata. `docs/python-runs.md:324` reflects completed simple plan construction and `:330` names disposition schema `3.0`.

No remaining material static finding was identified in the reviewed native slice. D08/D10 changes and their tests remain outside this certificate.

## 6. Verdict, acceptance and limits

**APPROVE, high confidence in the bounded implementation and inspected assertions.** With the separately reported successful installed execution, D20 and D21 meet the reviewed acceptance: the missing active-worker cancellation boundary is qualified through the native multiprocess executor, and the installed public composition dispatches, resumes, reconciles and processes retained captures with local-value parity. Existing lower-level recovery and budget tests remain part of D20's evidence for the other interruption/checkpoint boundaries.

The example aggregates exactly two native result messages; no scalable collector is promised. Recorded work and saved receipts do not measure every physical operation performed before an interruption.
