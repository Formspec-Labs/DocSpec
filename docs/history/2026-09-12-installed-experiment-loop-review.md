## 3. Data flow and invariants

**A successor is a complete source snapshot.** The example mutates the four-entry fixture mapping by adding one input, then passes that full mapping to the same builder. It does not treat `Supersedes` as append semantics or replace the catalog with only the new row (`offline_demo.py:176–183`). The original source namespace, versions and candidate tuples remain unchanged. The exclusion remains the qualified source item ID, so growth cannot accidentally bring the excluded file into the selected workload.

**Reuse is observed independently of saved counters.** The test wraps actual fetch, extractor, segmenter and processor methods and then runs the real example. The eight expected phase vectors are `(3,0,0,0)`, `(1,0,0,0)`, `(0,3,3,6)`, `(0,0,0,0)`, `(0,0,0,6)`, `(0,0,0,6)`, `(1,1,1,1)` and `(4,4,4,7)` (`test_offline_example.py:71–80`). Thus unchanged processing cannot silently re-fetch during alternatives/growth, and the clean run cannot accidentally inherit warm outputs. The separate locator histogram also verifies no fetch touched `out-of-scope` (`:68–70`). These are call counts at the selected implementation boundaries, not complete low-level I/O or wall-time measurements.

**The clean comparison has independent mutable state.** `LocalWorkspace.roots` uses explicit overrides only for `sourceCatalog` and `sourceContent`; reconciliation and its `processor-results.sqlite3` are below the fresh comparison root (`workspace.py:55–56`; `runtime/composition.py:259–265`). It is the sole clean run in that workspace. No base result is supplied. The observed final four fetches, four extraction/segmentation calls and seven processor calls provide a direct check against accidental reuse even if future storage assembly changes.

**Equal useful results need not have identical execution history.** Full phrase values and original source slices agree (`offline_demo.py:198`). Inspection also checks source/content/configuration dimensions over an untruncated comparison. Dispositions are keyed by source identity and compared after removing only entry identity and add/update classification, while both failure populations must be empty (`:200–211`). The comparison retains those excluded execution distinctions in its saved report. This is deliberate logical equality, not a claim that independently executed receipt/control bytes are identical.

**Pins and stage choices remain actual inputs.** `prepare_local_experiment` derives the ordinary plan from the provided stages/processors/resource descriptions and forwards to the same runtime (`runtime/experiments.py:106–134`). The example's case and resource alternatives change meaningful matching results, with expected match totals checked externally. Neither example nor probe adds a registry, resource resolver, scheduler, alternate processor runtime or custom result admission path.

**Provider-body capture is real acquisition through a controlled transport.** The fixture supplies one valid agency/body URL, while unrelated older invalid-agency cases keep their expected refusal. The new body scenario uses the admitted provider object and public catalog builder. The callback records the actual HTTPS request; exactly one call across capture and retained processing is required. It then compares exact captured bytes, three visible segments, their linked derived records and provider collection outcome (`installed_source_catalog_probe.py:583–633`). This proves the installed pipeline with controlled bytes, not live publisher availability or complete source collection.
