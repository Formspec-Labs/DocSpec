## 3. Data flow and invariants

1. **Publisher facts precede caller selection.** Bill status bytes are saved before offered-package selection (`examples/govinfo_bills.py:114–127`). All parsed status fields and formats enter metadata; only the explicit selected XML enters `candidateRenditions` (`:128–139`). GAO copies admitted provider fields and original evidence references before computing the caller's exact-label match (`examples/gao_topics.py:47–81`). A nonmatching label is retained as an ordinary fact, not treated as source rejection.
2. **Absence is not a fabricated document.** GAO contributes no report rendition (`examples/gao_topics.py:54–55`); the shared policy records this as unavailable for capture (`src/docspec/application/supplied_records_catalog.py:117–122`). Missing publisher topic fields remain provider refusals and create no catalog (`examples/gao_topics.py:112–120`). The supplied-record namespace and metadata clearly identify the mapping as caller-supplied data, while retaining the original source pin (`docs/gao-topics.md:36–45`).
3. **Exact bytes and interpreted text are distinct.** The bill bridge forwards `capture.body` unchanged (`examples/govinfo_bill_fetcher.py:95–99`). The visible representation and phrase matches use existing processing identities and enclosing source mappings. Segment quote offsets do not pretend to be exact offsets in XML markup; the guide says so (`docs/govinfo-bill-example.md:40–43`, `:59–63`).
4. **Refusals remain inspectable.** The bridge retains the original exception and bounded response when the provider supplies one (`examples/govinfo_bill_fetcher.py:34–48`, `:80–83`). `_finish` records failed-run inspection before raising (`examples/govinfo_bills.py:71–84`). GAO writes the unchanged provider report before branching on success/refusal (`examples/gao_topics.py:107–117`). It cannot relabel an unrelated output-path/provider failure as the expected missing-topic case.
5. **The provider owns source-specific limits.** The bill bridge forwards `max_bytes` unchanged; the provider takes `min(max_text_bytes, max_bytes)` and enforces streaming/count limits (`bill_acquisition.py:199–217`; `transport/capture.py:106–113`, `:133–163`, `:191–206`). The example bounds work to one record and 2 MiB of captured XML (`examples/govinfo_bills.py:139`, `:159`). GAO's mapping is bounded to ten records/1 MiB, with existing 8 MiB catalog scratch (`examples/gao_topics.py:58–61`). These limits do not claim a hard overall network wall-clock timeout; the guide describes individual transport waits (`docs/govinfo-bill-example.md:69–72`).
6. **CourtListener source values remain source values.** The provider's quoted ETag, size, timestamp and escaped URL flow directly into item/candidate values (`tools/courtlistener_bulk_source.py:211–225`). Dataset scope remains a DocSpec choice. Tombstones mean absence from the supplied later listing, not independently verified publisher deletion (`:190–195`). The retained page loader still reads a capture into memory; the provider's 8 MiB per-page parser bound is not a new whole-capture memory guarantee (`:133–150`; provider listing `:118–119`).
7. **Later processing demonstrably uses retained inputs.** Acquisition's context ends before the second prepared experiment (`examples/govinfo_bills.py:171–177`). The next run changes the pinned phrase resource and carries `base_release`; the example checks unchanged files/representations/segments and zero newly executed upstream output counts (`:178–187`). The installed probe observes the real provider method and rejects any call after client closure, so reuse is not inferred only from saved counts (`tests/support/govinfo_bill_probe.py:44–58`, `:79–88`).
8. **One package pin, separate data pins.** `vendor/spicy_docs.json:2–5`, `pyproject.toml:16–20`, `uv.lock:909–917` select the same wheel; the manifest SHA-256 independently matched `bef15f967b0840ccc119c812edca92b38c63adb8943074be17655b86c96f83f1`. The examples separately pin installed implementation files and source artifact/capture bytes. The manifest's source revision is recorded provenance, not an independently verified provider Git checkout in this review.

## 5. Findings and hypothesis resolution

**No actionable findings within this commit range.**

- **H1 — shared-wheel consolidation could make SpicyDocs mandatory or use checkout imports:** refuted by optional package declarations, lazy adapter imports, exact installed-member assertions and the two-stage core/reader-only environment checks.
- **H2 — the bill bridge could introduce a second publisher parser, infer a version, or erase refusals:** refuted by exact provider delegation, required package selection, preserved status/format metadata, source refusal files and failed-run assertions.
- **H3 — CourtListener parser replacement could change publisher values or weaken captured-population refusal:** refined. Quoted ETags and escaped URLs deliberately change the former normalized values; current candidates preserve provider values exactly, with no compatibility branch. Page-set consistency and pins remain, while the provider additionally rejects ambiguous bucket/truncation fields. Complete publisher coverage is not inferred from these retained pages.
- **H4 — the GAO example could turn unexpected/missing topics into selection policy or invent document availability:** refuted by intact provider rows, exact-label filtering, absent candidates and the no-catalog missing-topic failure path.
- **H5 — processing reuse could be a saved-counter claim alone:** refuted by observed provider call counts and client-closure assertions in the installed probe.

Review limits are deliberate: the synthetic fixtures establish the stated small source-to-dataset behavior, not current live availability, all legislative XML dialects, semantic interpretation, full publisher coverage or a separate native Dagster recipe implementation. The guides distinguish those limits. Existing CourtListener capture loading is not a streaming whole-corpus service, and this patch does not claim to make it one.
