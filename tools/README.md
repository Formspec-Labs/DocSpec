# Repository tools

Use the installed `docspec` command for supported application workflows. These
tools maintain generated artifacts, inspect retained samples, or reproduce
specific qualification evidence. They are not installed package APIs.

Catalog policy creation now lives in the CLI:

```sh
uv run --frozen --extra dagster docspec source-catalog write-policy \
  --policy federal-register --input fields.json --output policy-member.json
```

The command uses the application policy's own parser and serializer, verifies
the round trip, and refuses an existing output. See the
[catalog guide](../docs/catalog-and-processing.md) for inputs and the complete flow.

| --- | --- | --- |

The companion joins unique documents; its counts are not the number of sample-stratum memberships. |
| Compare catalog topics with publisher responses | [fr_topic_receipt.py](fr_topic_receipt.py) | Owns the topic strata and records live observations separately from retained catalog facts. Tests replace publisher calls with local responses. |
| Select, fetch, and summarize an attachment sample | [select_attachment_sample.py](select_attachment_sample.py), [fetch_attachment_sample.py](fetch_attachment_sample.py), [summarize_attachment_sample.py](summarize_attachment_sample.py) | Keep selection weights, acquisition receipts, quota handling, and report calculations explicit. `tests/test_attachment_sample_tools.py` covers local behavior, including interrupted receipt recovery. |
| Draw and calibrate a retention-floor population | [draw_pdf_floor_population.py](draw_pdf_floor_population.py), [calibrate_retention_floors.py](calibrate_retention_floors.py) | Corpus measurement tools; the installed retention-floor implementation owns how declared calibration evidence is interpreted. |
| Reproduce the historical FR/Mirrulations portable mint | [build_document_release.py](build_document_release.py), [fr_mirrulations_pin.py](fr_mirrulations_pin.py) | A fixed-corpus recipe with pinned captures and rescue pointers. `tests/test_document_release_builder.py` and `tests/test_qualification_corpus_pin.py` check its retained evidence and behavior. |
| Prove a CourtListener source population and acquisition route | [courtlistener_bulk_source.py](courtlistener_bulk_source.py) | Digest-pinned publisher-listing proof, exercised by `tests/test_courtlistener_bulk_source.py`. It is not a production source-native provider. |
| Maintain generated schemas and verifier fixtures | [generate_scale_profile_schema.py](generate_scale_profile_schema.py), [restamp_document_release_fixtures.py](restamp_document_release_fixtures.py) | Active maintenance recipes; follow the [schema guide](../docs/schema-maintenance.md) and use check mode before changing generated bytes. |
| Share retained catalog file reading | [catalog_sample_support.py](catalog_sample_support.py) | Internal helper for manifest ordering, plain/gzip JSONL rows, and receipt paths. It does not verify or admit a catalog for publication. |

Run a tool from the repository root with `uv run --frozen --extra dagster python
-m tools.<module> --help` when it provides a command. Read its input requirements
before selecting live acquisition. Focused tests use local inputs and substitutes
for publisher requests.

## Keep historical reproduction distinct from product integration

The portable release format remains supported. The fixed FR/Mirrulations mint
reproduces a completed campaign and reads its historical qualification metadata,
candidate shape, and retained captures. Its current executable consumers are the
recipe, its calibration chain, and tests; no current product caller was found in
the September 11 review.

That recipe already shares portable identity, coverage, and verification rules
with the package. Its remaining assembly assumes document and attachment bodies,
empty comment output, and campaign-specific refusals. Moving it into the package
would require a new supported input model and a real caller. The application
release lifecycle produces a different representation and does not reproduce
the historical portable bytes.

Keep shared product rules with their package owner. Share tool code when its
callers read the same evidence in the same way; keep each research question,
sampling rule, and receipt meaning with its tool. A tool is superseded when a
current implementation serves its purpose and consumers, not merely when its
filename resembles a package module.
